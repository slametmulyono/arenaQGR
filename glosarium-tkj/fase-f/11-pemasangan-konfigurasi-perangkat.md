# 11 · Pemasangan dan Konfigurasi Perangkat Jaringan

> **Fase:** F (Kelas XI–XII) · **Elemen CP:** Pemasangan dan Konfigurasi Perangkat Jaringan (memasang dan mengganti perangkat; konsep, konfigurasi, dan pengujian VLAN; proses dan jenis routing; routing statis dan dinamis; NAT dan internet gateway; proxy server; manajemen bandwidth; load balancing)
>
> **Ringkasan:** Inilah "dapur" konfigurasi TKJ: cara mengakses router/switch (console, Winbox, SSH), konsep switching (MAC table, VLAN, trunk, STP), routing statis dan dinamis (RIP, OSPF, BGP), NAT dan firewall dasar, manajemen bandwidth (queue), load balancing, hotspot, PPPoE, dan istilah khas MikroTik serta Cisco yang paling sering dipakai di sekolah dan industri.

| No | Istilah | Pengertian | Fungsi / Kegunaan |
|---:|---|---|---|
| 1 | **Perangkat Jaringan Aktif vs Pasif** | Aktif: butuh listrik dan memproses sinyal (router, switch, AP, media converter, ONT). Pasif: tidak butuh listrik (kabel, patch panel, keystone, splitter FO, konektor). | Menyusun daftar perangkat dan merencanakan kebutuhan daya/PoE. |
| 2 | **Pemasangan Perangkat (Mounting)** | Memasang perangkat di rak (rackmount dengan bracket dan cage nut), di dinding (wall-mount), di plafon (AP), atau tiang (radio) sesuai petunjuk, dengan ventilasi, kabel daya, grounding, dan label. | Perangkat aman, dingin, rapi, dan mudah dirawat. |
| 3 | **Penggantian Perangkat (Replacement)** | Prosedur mengganti perangkat rusak/usang: backup konfigurasi lama → siapkan pengganti dengan konfigurasi setara → jadwalkan downtime → tukar fisik → restore/konfigurasi → uji → perbarui dokumentasi. | Gangguan minimal dan konfigurasi tidak hilang. |
| 4 | **Konfigurasi Awal (Initial Setup)** | Langkah pertama pada perangkat baru: akses lewat console/IP default, ganti kata sandi admin, atur hostname, alamat IP manajemen, zona waktu/NTP, perbarui firmware, nonaktifkan layanan tak perlu. | Dasar keamanan dan kerapian sebelum konfigurasi lanjutan. |
| 5 | **Port Console dan Terminal 9600 8N1** | Port serial pada router/switch untuk akses langsung tanpa jaringan. Pengaturan terminal standar: 9600 baud, 8 data bit, no parity, 1 stop bit, tanpa flow control. | Akses saat perangkat belum punya IP, salah konfigurasi, atau lupa kata sandi. |
| 6 | **Akses Manajemen (Console, Telnet, SSH, Web, Winbox, API)** | Cara mengelola perangkat: console (lokal), Telnet (tidak aman), SSH (aman, port 22), WebFig/HTTP(S), Winbox (GUI MikroTik, port 8291), API/REST (otomasi). | Memilih metode yang aman dan sesuai kebutuhan; Telnet/HTTP sebaiknya dimatikan. |
| 7 | **MikroTik RouterOS dan RouterBOARD** | RouterOS: sistem operasi router MikroTik (juga bisa dipasang di PC/VM sebagai CHR/x86) dengan fitur routing, firewall, hotspot, wireless, VPN. RouterBOARD: perangkat keras MikroTik (hAP, RB750/hEX, CCR, CRS). Level lisensi 4–6 membedakan batas fitur. | Router paling populer di sekolah, RT/RW Net, dan ISP kecil–menengah Indonesia. |
| 8 | **Winbox** | Aplikasi Windows (jalan juga di Linux/macOS via Wine atau versi native) untuk mengelola MikroTik lewat GUI, bisa terhubung via IP atau MAC address (tanpa IP, hanya satu segmen Layer 2). | Konfigurasi MikroTik yang cepat dan visual; penyelamat saat IP salah. |
| 9 | **WebFig, Quick Set, dan Terminal RouterOS** | WebFig: antarmuka web MikroTik. Quick Set: wizard konfigurasi cepat (Home AP, PTP Bridge, CPE). Terminal: CLI RouterOS dengan struktur menu seperti `/ip address print`. | Alternatif pengelolaan MikroTik selain Winbox. |
| 10 | **Konfigurasi Default MikroTik** | Perangkat baru biasanya: IP 192.168.88.1/24 di ether2–5 (bridge), ether1 sebagai WAN (DHCP client), user `admin` tanpa/dengan kata sandi bawaan, DHCP server aktif, NAT masquerade. Bisa dihapus dengan "Remove Configuration" atau `/system reset-configuration no-defaults=yes`. | Titik awal praktik; menghapusnya memberi kanvas kosong untuk belajar. |
| 11 | **Cisco IOS dan Mode CLI** | Sistem operasi perangkat Cisco dengan mode bertingkat: **User EXEC** (`Router>`), **Privileged EXEC** (`Router#`, masuk dengan `enable`), **Global Configuration** (`Router(config)#`, masuk dengan `configure terminal`), lalu sub-mode interface/router/line. | Struktur perintah yang dipelajari lewat Packet Tracer dan CCNA. |
| 12 | **Running-config vs Startup-config** | Running-config: konfigurasi aktif di RAM (hilang saat restart). Startup-config: konfigurasi tersimpan di NVRAM yang dimuat saat boot. Simpan dengan `copy running-config startup-config` atau `write memory`. | Lupa menyimpan adalah kesalahan klasik yang membuat konfigurasi hilang setelah reboot. |
| 13 | **Perintah Show Penting (Cisco)** | `show running-config`, `show ip interface brief` (status IP semua port), `show ip route` (tabel routing), `show vlan brief`, `show interfaces`, `show mac address-table`, `show cdp neighbors`, `show version`. | Memeriksa dan menganalisis kondisi perangkat. |
| 14 | **Hostname, Banner, Password, dan Enable Secret** | Konfigurasi identitas dan pengamanan dasar Cisco: `hostname SW1`, `banner motd #Dilarang masuk#`, `enable secret rahasia` (terenkripsi), `line console 0`/`line vty 0 4` + `password` + `login`, `service password-encryption`. | Mengamankan akses perangkat sejak konfigurasi pertama. |
| 15 | **Interface dan Penamaan Port** | Cisco: `FastEthernet0/1`, `GigabitEthernet0/0/1`, `Serial0/0/0`, `Vlan1`. MikroTik: `ether1`, `sfp1`, `wlan1`, `bridge1`, `vlan10`, `pppoe-out1`. | Menunjuk port yang benar saat konfigurasi. |
| 16 | **Status Interface (up/down, administratively down)** | "up/up": fisik dan protokol aktif. "down/down": tidak ada link fisik. "administratively down": dimatikan admin (`shutdown`), dihidupkan dengan `no shutdown`. MikroTik: flag R (running), X (disabled). | Langkah awal troubleshooting: pastikan interface hidup. |
| 17 | **Backup dan Restore Konfigurasi** | MikroTik: `/system backup save` (biner) dan `/export file=cfg` (teks .rsc). Cisco: `copy running-config tftp` atau salin teks running-config. Simpan di luar perangkat dan beri tanggal. | Pemulihan cepat saat perangkat rusak atau salah konfigurasi. |
| 18 | **Firmware Upgrade dan Netinstall** | Memperbarui RouterOS (`/system package update`) beserta RouterBOOT; Netinstall adalah alat MikroTik untuk instal ulang RouterOS lewat jaringan saat perangkat rusak/lupa kata sandi (menghapus semua konfigurasi). | Menutup celah keamanan dan menyelamatkan perangkat yang "bricked". |
| 19 | **Factory Reset** | Mengembalikan perangkat ke pengaturan pabrik lewat tombol reset (tekan saat menyala 5–10 detik) atau perintah. | Memulai konfigurasi dari nol atau mengatasi lupa kata sandi. |
| 20 | **Switching (Cara Kerja Switch)** | Switch mempelajari MAC asal setiap frame yang masuk (learning), mencatatnya per port di MAC address table (CAM table), meneruskan frame ke port tujuan (forwarding), membanjiri ke semua port jika tujuan belum dikenal (flooding), dan membuang frame ke port asal (filtering). | Dasar memahami VLAN, port security, dan masalah loop. |
| 21 | **MAC Address Table (CAM Table)** | Tabel di switch berisi pasangan MAC address–port–VLAN dengan masa berlaku (aging, default 300 detik). Cisco: `show mac address-table`. MikroTik: `/interface bridge host print`. | Melacak di port mana suatu perangkat terhubung. |
| 22 | **Managed vs Unmanaged Switch** | Unmanaged: colok langsung bekerja, tanpa konfigurasi (rumah/kelas kecil). Managed: bisa dikonfigurasi (VLAN, QoS, port security, SNMP, link aggregation); smart/web-managed ada di tengahnya. | Jaringan sekolah/kantor butuh managed switch untuk VLAN dan pemantauan. |
| 23 | **Switch Layer 2 vs Layer 3** | L2: hanya meneruskan berdasarkan MAC. L3: juga bisa routing antar-VLAN dengan SVI dan routing statis/dinamis pada kecepatan hardware. MikroTik CRS dengan RouterOS bersifat L3. | Memilih perangkat distribusi/core. |
| 24 | **Bridge (MikroTik) dan Hardware Offload** | Di RouterOS, bridge menggabungkan beberapa port fisik/wireless menjadi satu segmen Layer 2. Hardware offload (H flag) berarti switching ditangani chip switch, bukan CPU, sehingga cepat. | Membuat "switch" dari port router dan memahami batas kinerja. |
| 25 | **VLAN (Virtual LAN)** | Pemisahan satu switch fisik menjadi beberapa jaringan logis terpisah (broadcast domain berbeda) berdasarkan nomor VLAN ID 1–4094, misalnya VLAN 10 Guru, VLAN 20 Siswa, VLAN 99 Manajemen. Antar-VLAN tidak bisa berkomunikasi tanpa router/L3. | Keamanan, pengurangan broadcast, dan pengelompokan pengguna tanpa menambah switch. |
| 26 | **VLAN ID, Default VLAN, dan Native VLAN** | VLAN ID: nomor identitas. Default VLAN: VLAN 1 tempat semua port berada awalnya (sebaiknya tidak dipakai produksi). Native VLAN: VLAN yang dikirim tanpa tag pada trunk (default 1; disarankan diubah dan disamakan kedua ujung). | Menghindari kebocoran antar-VLAN dan pesan "native VLAN mismatch". |
| 27 | **Access Port** | Port switch yang menjadi anggota satu VLAN dan tidak menyertakan tag; untuk PC, printer, IP phone. Cisco: `switchport mode access` + `switchport access vlan 10`. | Menempatkan perangkat pengguna ke VLAN tertentu. |
| 28 | **Trunk Port dan IEEE 802.1Q (Tagging)** | Trunk: port yang membawa banyak VLAN sekaligus (antar-switch, ke router/AP) dengan menambahkan tag 4 byte 802.1Q pada frame yang berisi VLAN ID. Cisco: `switchport mode trunk` + `switchport trunk allowed vlan 10,20`. | Satu kabel untuk semua VLAN antar-perangkat. |
| 29 | **Tagged vs Untagged (Istilah MikroTik/HP/TP-Link)** | Tagged = port trunk yang membawa VLAN dengan tag; untagged = port access yang menerima/mengirim tanpa tag untuk satu VLAN (PVID). MikroTik: `/interface bridge vlan add tagged=... untagged=...` dengan `vlan-filtering=yes`. | Menerjemahkan konsep VLAN Cisco ke perangkat merek lain. |
| 30 | **PVID (Port VLAN ID)** | VLAN yang diberikan pada frame tanpa tag yang masuk ke sebuah port (padanan access VLAN). | Menentukan VLAN perangkat pengguna pada switch non-Cisco. |
| 31 | **Inter-VLAN Routing** | Menghubungkan VLAN yang berbeda melalui perangkat Layer 3: router (router-on-a-stick), switch L3 (SVI), atau MikroTik dengan interface VLAN. | Guru bisa mengakses server di VLAN lain sesuai kebijakan. |
| 32 | **Router-on-a-Stick dan Subinterface** | Satu port router terhubung trunk ke switch dan dibagi menjadi subinterface per VLAN (`interface g0/0.10` + `encapsulation dot1Q 10` + IP gateway VLAN 10). MikroTik: `/interface vlan add name=vlan10 vlan-id=10 interface=ether2` lalu beri IP. | Inter-VLAN routing murah dengan satu port fisik. |
| 33 | **SVI (Switch Virtual Interface)** | Interface logis `interface Vlan10` pada switch L3 yang diberi IP dan menjadi gateway VLAN; perlu `ip routing` aktif. | Inter-VLAN routing berkecepatan tinggi di switch core/distribution. |
| 34 | **VTP (VLAN Trunking Protocol)** | Protokol Cisco untuk menyebarkan daftar VLAN dari switch server ke client dalam satu domain; berisiko menghapus VLAN jika salah kelola. Mode: server, client, transparent. | Mengurangi pekerjaan membuat VLAN di banyak switch; sering dimatikan (transparent) demi keamanan. |
| 35 | **DTP (Dynamic Trunking Protocol)** | Protokol Cisco yang menegosiasikan trunk secara otomatis; sebaiknya dimatikan (`switchport nonegotiate`) dan trunk diatur manual. | Mencegah serangan VLAN hopping lewat trunk otomatis. |
| 36 | **Loop Layer 2 dan Broadcast Storm** | Jika dua switch terhubung lewat lebih dari satu jalur tanpa STP, frame broadcast berputar tanpa henti, membanjiri jaringan (storm) hingga lumpuh; LED semua port berkedip cepat. | Alasan STP wajib aktif dan kabel tidak boleh dicolok sembarangan antar-switch. |
| 37 | **STP / RSTP / MSTP (Spanning Tree Protocol)** | Protokol yang mencegah loop dengan memblokir jalur cadangan: STP (802.1D, konvergensi 30–50 detik), RSTP (802.1w, beberapa detik), MSTP (802.1s, per kelompok VLAN), PVST+ (Cisco per VLAN). | Redundansi kabel antar-switch tanpa broadcast storm. |
| 38 | **Root Bridge, BPDU, dan Port Role** | Root bridge: switch pusat pohon STP (bridge ID terkecil: priority + MAC). BPDU: pesan STP antar-switch. Port role: root port, designated port, blocked/alternate port. | Mengatur switch core sebagai root (`spanning-tree vlan 1 priority 4096`). |
| 39 | **PortFast, BPDU Guard, dan Root Guard** | PortFast: port ke PC langsung forwarding tanpa menunggu STP. BPDU Guard: mematikan port jika menerima BPDU (ada switch liar). Root Guard: mencegah switch lain menjadi root. | Mempercepat koneksi klien dan melindungi topologi STP. |
| 40 | **Link Aggregation (EtherChannel, LACP, Bonding)** | Menggabungkan 2–8 port fisik menjadi satu link logis untuk bandwidth lebih besar dan redundansi. Standar LACP (802.3ad/802.1AX); Cisco menyebut EtherChannel (PAgP/LACP); MikroTik/Linux menyebut bonding. | Uplink switch-ke-switch atau server yang lebih besar tanpa membeli port 10G. |
| 41 | **Port Security** | Fitur switch membatasi MAC address yang boleh terhubung ke suatu port (jumlah maksimum, MAC tertentu, sticky) dengan aksi shutdown/restrict/protect saat dilanggar. | Mencegah orang mencolokkan perangkat/switch liar ke port kelas. |
| 42 | **Port Mirroring (SPAN)** | Menyalin lalu lintas dari satu/beberapa port ke port pemantau tempat Wireshark/IDS terpasang. | Analisis paket tanpa mengganggu lalu lintas asli. |
| 43 | **Storm Control dan IGMP Snooping** | Storm control membatasi persentase broadcast/multicast per port. IGMP snooping membuat switch hanya meneruskan multicast (IPTV, CCTV) ke port yang berlangganan. | Menjaga LAN tetap responsif saat ada banyak broadcast/multicast. |
| 44 | **Jumbo Frame** | Frame Ethernet lebih besar dari 1500 byte (biasanya 9000 byte) untuk efisiensi transfer besar antar-server/NAS; semua perangkat di jalur harus mendukung. | Meningkatkan throughput storage/backup di jaringan server. |
| 45 | **CDP, LLDP, dan MNDP (Neighbor Discovery)** | Protokol pengenalan perangkat tetangga: CDP (Cisco), LLDP (standar, juga LLDP-MED untuk IP phone), MNDP (MikroTik, tampil di Winbox Neighbors). | Mengetahui perangkat apa terhubung di port mana tanpa menelusuri kabel. |
| 46 | **DHCP Server pada Router/Switch** | Router memberi IP otomatis ke klien. MikroTik: `/ip pool` + `/ip dhcp-server` + `/ip dhcp-server network` (gateway, DNS) atau wizard DHCP Setup. Cisco: `ip dhcp pool LAN` + `network` + `default-router` + `dns-server` + `ip dhcp excluded-address`. | Layanan pengalamatan otomatis di gateway tanpa server terpisah. |
| 47 | **DHCP Relay / IP Helper** | Meneruskan permintaan DHCP (broadcast) dari VLAN/subnet lain ke DHCP server terpusat: Cisco `ip helper-address 10.10.10.5` di SVI; MikroTik `/ip dhcp-relay`. | Satu DHCP server melayani banyak VLAN. |
| 48 | **DHCP Client (WAN) dan Static WAN** | Router mendapat IP dari ISP secara otomatis (DHCP client di ether1) atau diberi IP publik statis oleh ISP (beserta gateway dan DNS). | Menghubungkan router ke internet. |
| 49 | **DNS pada Router (Forwarder/Cache, Allow Remote Requests, Static DNS)** | Router meneruskan permintaan DNS klien ke server upstream (8.8.8.8, 1.1.1.1, DNS ISP) dan menyimpan cache. MikroTik: `/ip dns set servers=... allow-remote-requests=yes`; static entry untuk nama lokal (server.sekolah.local). Port 53 harus difilter dari sisi WAN. | Klien cukup memakai IP router sebagai DNS; resolusi lebih cepat. |
| 50 | **Routing** | Proses router memilih jalur dan meneruskan paket dari satu jaringan ke jaringan lain berdasarkan alamat IP tujuan dan tabel routing. Setiap router memutuskan hop berikutnya (next hop) secara mandiri. | Menghubungkan subnet, VLAN, kantor cabang, dan internet. |
| 51 | **Tabel Routing (Routing Table)** | Daftar rute yang dikenal router: jaringan tujuan/prefix, gateway/next hop, interface keluar, metric, distance, dan asal rute (connected, static, dynamic). Cisco: `show ip route` (C, S, R, O, B). MikroTik: `/ip route print` (DAC, AS, DAo). | Pusat keputusan router; membacanya adalah kunci troubleshooting routing. |
| 52 | **Connected Route dan Longest Prefix Match** | Connected: rute otomatis ke subnet yang langsung terpasang di interface. Longest prefix match: jika ada beberapa rute cocok, router memilih yang prefix-nya paling spesifik (/24 mengalahkan /16, /0 paling akhir). | Menjelaskan urutan prioritas rute di tabel. |
| 53 | **Static Routing (Routing Statis)** | Rute yang ditulis manual oleh admin: Cisco `ip route 192.168.2.0 255.255.255.0 10.0.0.2`; MikroTik `/ip route add dst-address=192.168.2.0/24 gateway=10.0.0.2`. Tidak berubah sendiri jika jalur putus. | Sederhana, aman, dan hemat sumber daya untuk jaringan kecil atau rute khusus. |
| 54 | **Default Route (0.0.0.0/0, Gateway of Last Resort)** | Rute "ke mana saja yang tidak ada di tabel", biasanya menuju ISP: Cisco `ip route 0.0.0.0 0.0.0.0 <gateway>`; MikroTik `dst-address=0.0.0.0/0`. | Rute wajib agar jaringan lokal bisa ke internet. |
| 55 | **Dynamic Routing (Routing Dinamis)** | Router saling bertukar informasi rute secara otomatis lewat protokol routing dan menyesuaikan tabel saat topologi berubah. | Jaringan besar/berubah-ubah tanpa menulis rute manual di setiap router. |
| 56 | **Protokol Routing: IGP vs EGP** | IGP (Interior Gateway Protocol) dipakai di dalam satu organisasi: RIP, OSPF, EIGRP, IS-IS. EGP (Exterior) antar-organisasi/ISP: BGP. | Memilih protokol sesuai skala dan kepemilikan jaringan. |
| 57 | **Distance Vector vs Link State** | Distance vector (RIP, EIGRP): router hanya tahu "jarak dan arah" dari tetangga (rumor). Link state (OSPF, IS-IS): setiap router punya peta lengkap topologi dan menghitung jalur terpendek (SPF/Dijkstra). | Memahami kecepatan konvergensi dan skala tiap protokol. |
| 58 | **Metric** | Nilai "biaya" suatu rute menurut protokol: RIP = hop count, OSPF = cost (100 Mbps / bandwidth), EIGRP = gabungan bandwidth dan delay. Rute dengan metric terkecil menang dalam protokol yang sama. | Menentukan jalur terbaik di antara beberapa jalur. |
| 59 | **Administrative Distance (AD) / Distance** | Tingkat kepercayaan sumber rute jika prefix sama dari protokol berbeda (kecil = lebih dipercaya): connected 0, static 1, eBGP 20, EIGRP 90, OSPF 110, RIP 120, iBGP 200. MikroTik menyebutnya distance dan bisa diubah untuk failover. | Router memilih rute dari sumber yang lebih dipercaya. |
| 60 | **Konvergensi** | Waktu yang dibutuhkan semua router menyepakati topologi baru setelah perubahan (link putus/naik). RIP lambat (menit), OSPF/EIGRP cepat (detik). | Semakin cepat konvergensi, semakin singkat gangguan pengguna. |
| 61 | **RIP (Routing Information Protocol) v1/v2** | Protokol distance vector paling sederhana: metric hop count, maksimal 15 hop (16 = tak terjangkau), update tiap 30 detik. RIPv2 mendukung VLSM/CIDR dan multicast 224.0.0.9. Cisco: `router rip` + `version 2` + `network 192.168.1.0` + `no auto-summary`. MikroTik: `/routing rip`. | Bagus untuk belajar routing dinamis dan jaringan kecil; jarang dipakai di produksi. |
| 62 | **OSPF (Open Shortest Path First)** | Protokol link state standar terbuka yang membagi jaringan menjadi area (Area 0 = backbone), bertukar LSA, memilih DR/BDR di segmen multi-akses, metric cost berdasarkan bandwidth, konvergensi cepat, mendukung autentikasi. Cisco: `router ospf 1` + `network 10.0.0.0 0.0.0.255 area 0`. MikroTik: `/routing ospf instance` + `area` + `interface-template`. | Protokol routing dinamis utama di jaringan kampus, perusahaan, dan ISP internal. |
| 63 | **Istilah OSPF: Router ID, Area, LSA, LSDB, DR/BDR, Neighbor/Adjacency, Wildcard Mask** | Router ID: identitas router (IP tertinggi/loopback). LSA: paket informasi link. LSDB: basis data topologi. DR/BDR: router perwakilan di segmen Ethernet. Neighbor state harus FULL. Wildcard mask: kebalikan subnet mask (0.0.0.255 untuk /24). | Membaca `show ip ospf neighbor` dan menyelesaikan masalah OSPF. |
| 64 | **EIGRP (Enhanced Interior Gateway Routing Protocol)** | Protokol hibrid milik Cisco (kini terbuka) dengan konvergensi sangat cepat (algoritma DUAL), metric gabungan bandwidth-delay, dan rute cadangan (feasible successor). AD 90. | Alternatif OSPF di lingkungan Cisco murni. |
| 65 | **BGP (Border Gateway Protocol)** | Protokol routing antar-Autonomous System yang menjalankan internet; memilih jalur berdasarkan kebijakan dan atribut (AS path, local preference), bukan sekadar kecepatan. eBGP antar-AS, iBGP dalam AS. Port TCP 179. | Wajib bagi ISP/perusahaan yang punya ASN dan IP publik sendiri; dikenalkan di Fase F. |
| 66 | **IS-IS** | Protokol link state lain yang setara OSPF, banyak dipakai di backbone operator besar. | Pengetahuan umum saat membaca dokumentasi ISP. |
| 67 | **Redistribusi Rute (Redistribution)** | Menyalin rute dari satu protokol/sumber ke protokol lain (misalnya static ke OSPF, OSPF ke BGP). | Menggabungkan jaringan yang memakai protokol berbeda. |
| 68 | **Floating Static Route dan Failover Routing** | Rute statis cadangan dengan distance lebih besar (misalnya 1 untuk ISP utama, 2 untuk ISP cadangan) yang hanya aktif jika rute utama hilang. Di MikroTik dilengkapi `check-gateway=ping` agar rute mati saat gateway tidak merespons. | Internet tetap hidup otomatis saat ISP utama putus. |
| 69 | **Recursive Routing dan Netwatch** | Recursive: gateway rute ditentukan lewat rute lain (misalnya memantau 8.8.8.8 lewat ISP1) agar failover mendeteksi putus di luar gateway langsung. Netwatch: alat MikroTik memantau host dan menjalankan skrip saat up/down. | Failover yang lebih cerdas daripada sekadar cek gateway. |
| 70 | **Load Balancing (Penyeimbangan Beban)** | Membagi lalu lintas ke beberapa jalur/ISP agar bandwidth gabungan termanfaatkan: ECMP (per koneksi berdasarkan rute berbobot sama), PCC (Per Connection Classifier di mangle MikroTik), Nth, atau berbasis alamat. Bukan menjumlahkan kecepatan untuk satu unduhan. | Memanfaatkan dua atau lebih langganan internet secara bersamaan sekaligus failover. |
| 71 | **PCC (Per Connection Classifier)** | Metode load balancing MikroTik yang membagi koneksi berdasarkan hash alamat/port (misalnya both-addresses:2/0 dan 2/1) lalu menandai routing mark per ISP di mangle. | Load balancing yang menjaga satu koneksi tetap di satu ISP (penting untuk login situs). |
| 72 | **Policy Based Routing (PBR) dan Routing Mark** | Routing berdasarkan kebijakan (asal, port, jenis trafik), bukan hanya tujuan: MikroTik menandai paket di mangle (`routing-mark`) lalu memakai tabel routing terpisah; Cisco memakai route-map. | Misalnya: lab ujian lewat ISP dedicated, hotspot siswa lewat ISP murah. |
| 73 | **NAT (Network Address Translation)** | Penerjemahan alamat IP pada router saat paket melewati batas jaringan, umumnya IP privat LAN menjadi IP publik WAN. Jenis: Source NAT (masquerade/PAT), Destination NAT (port forwarding), Static NAT 1:1. | Banyak perangkat berbagi satu IP publik dan jaringan lokal tersembunyi dari internet. |
| 74 | **Masquerade / PAT / NAT Overload (Source NAT)** | Semua IP privat diganti menjadi IP WAN router dengan port sumber berbeda untuk membedakan koneksi.
