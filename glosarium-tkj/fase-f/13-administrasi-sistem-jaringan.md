# 13 · Administrasi Sistem Jaringan (Server)

> **Fase:** F (Kelas XI–XII) · **Elemen CP:** Administrasi Sistem Jaringan (instalasi sistem operasi jaringan; konsep, instalasi, konfigurasi, dan pengujian remote server, DHCP server, DNS server, FTP server, file server, web server, mail server, database server, control panel hosting, shared hosting, dedicated hosting, VPS, VPN server; sistem kontrol dan monitoring)
>
> **Ringkasan:** Server adalah "jantung layanan" jaringan. Bagian ini berisi istilah instalasi OS server, akses jarak jauh (SSH), tiap layanan server beserta perangkat lunak populernya (isc-dhcp, BIND9, Apache/Nginx, vsftpd, Samba, Postfix/Dovecot, MariaDB), hosting dan VPS, virtualisasi/container, serta pemantauan (Zabbix, Cacti, Grafana) dan perawatan server.

| No | Istilah | Pengertian | Fungsi / Kegunaan |
|---:|---|---|---|
| 1 | **Administrasi Sistem Jaringan** | Pekerjaan memasang, mengonfigurasi, mengamankan, memantau, dan merawat server beserta layanan jaringannya agar tersedia bagi pengguna. Pelakunya disebut system administrator (sysadmin). | Layanan sekolah/kantor (internet, web, email, file, e-learning) bergantung pada administrasi yang baik. |
| 2 | **Sistem Operasi Jaringan (Network Operating System)** | OS yang dirancang melayani banyak klien dan menjalankan layanan jaringan: Debian, Ubuntu Server, Rocky/AlmaLinux (RHEL), openSUSE, FreeBSD, Windows Server. Umumnya tanpa GUI (headless) demi kinerja dan keamanan. | Fondasi semua server; Debian/Ubuntu Server paling umum di praktik SMK. |
| 3 | **Instalasi OS Server (Minimal Install)** | Instalasi tanpa desktop: pilih bahasa/zona waktu, partisi (root, swap, /home atau LVM), pengguna admin, paket minimal + OpenSSH server, lalu update. Di VM: alokasikan CPU/RAM/disk secukupnya, jaringan bridged. | Server ringan, cepat, dan hanya berisi yang dibutuhkan. |
| 4 | **Pasca-Instalasi Server (Baseline)** | Langkah setelah instal: set hostname dan IP statis, `apt update && apt upgrade`, buat user sudo, konfigurasi SSH key, firewall ufw, NTP, zona waktu, dan snapshot/backup awal. | Dasar aman sebelum memasang layanan apa pun. |
| 5 | **Remote Server / Administrasi Jarak Jauh** | Mengelola server dari komputer lain lewat jaringan: SSH (CLI), RDP/VNC (GUI), web panel (Webmin, Cockpit), atau IPMI/iLO/iDRAC (akses hardware). | Server di rak/data center dikelola tanpa monitor dan keyboard fisik. |
| 6 | **OpenSSH Server (sshd)** | Layanan SSH di Linux: instal `apt install openssh-server`, konfigurasi `/etc/ssh/sshd_config` (Port, PermitRootLogin, PasswordAuthentication), restart `systemctl restart ssh`, akses dari klien `ssh user@ip -p 22`. | Layanan remote server pertama yang dipasang dan diuji di praktik. |
| 7 | **SCP, SFTP, dan rsync** | Cara menyalin file lewat SSH: `scp file user@ip:/tujuan`, klien SFTP (FileZilla, WinSCP), `rsync -avz` (sinkronisasi efisien, hanya perubahan yang dikirim). | Memindahkan file dan backup antar-server dengan aman. |
| 8 | **Webmin dan Cockpit** | Panel administrasi berbasis web untuk server Linux: Webmin (port 10000, sangat lengkap), Cockpit (port 9090, bawaan RHEL/Fedora). | Mengelola server lewat browser bagi yang belum lancar CLI. |
| 9 | **Layanan (Service) dan Port Listening** | Setiap layanan server "mendengarkan" di port tertentu; cek dengan `ss -tulpn` atau `netstat -tulpn`, kelola dengan `systemctl status/start/enable`. | Memastikan layanan aktif sebelum diuji dari klien. |
| 10 | **DHCP Server (isc-dhcp-server, Kea, dnsmasq, Windows DHCP)** | Server pemberi IP otomatis. Di Debian/Ubuntu: `isc-dhcp-server` (file `/etc/dhcp/dhcpd.conf`: subnet, range, option routers, option domain-name-servers, default-lease-time) dan interface di `/etc/default/isc-dhcp-server`. Kea adalah penerusnya. | Layanan dasar yang menghidupkan jaringan klien tanpa konfigurasi manual. |
| 11 | **Proses DORA dan Lease** | Discover (klien broadcast mencari server) → Offer (server menawarkan IP) → Request (klien meminta) → Acknowledge (server mengesahkan). Lease: masa pinjam IP; klien memperbarui pada 50% masa (T1). | Memahami log DHCP dan masalah "tidak dapat IP". |
| 12 | **Scope/Subnet, Range/Pool, Exclusion, Reservation, Option** | Scope: subnet yang dilayani. Range: rentang IP yang dibagikan. Exclusion: IP yang tidak dibagikan (untuk statis). Reservation: IP tetap untuk MAC tertentu (`host printer { hardware ethernet ...; fixed-address ...; }`). Option: info tambahan (gateway, DNS, domain, NTP, TFTP untuk PXE/VoIP). | Komponen konfigurasi DHCP yang harus dipahami dan diuji. |
| 13 | **Pengujian DHCP Server** | Di klien: `ipconfig /release` lalu `/renew` (Windows) atau `dhclient -v` (Linux); periksa IP dari range, gateway, DNS; di server lihat `/var/lib/dhcp/dhcpd.leases` dan `journalctl -u isc-dhcp-server`. | Bukti layanan berjalan sesuai rancangan. |
| 14 | **DNS Server (BIND9, Unbound, dnsmasq, PowerDNS, Windows DNS)** | Server penerjemah nama. BIND9 paling umum di praktik: paket `bind9`, konfigurasi `/etc/bind/named.conf.local` (zona), `named.conf.options` (forwarders, recursion), file zona di `/etc/bind/db.namadomain`. Unbound untuk resolver cache ringan. | Nama domain lokal (sekolah.sch.id, server.lab) dan cache DNS untuk seluruh jaringan. |
| 15 | **Zona Forward dan Zona Reverse** | Forward zone: nama → IP (file berisi record A). Reverse zone: IP → nama (zona `in-addr.arpa`, record PTR), misalnya 192.168.1.0/24 menjadi `1.168.192.in-addr.arpa`. | Resolusi dua arah; reverse dibutuhkan mail server dan log yang rapi. |
| 16 | **Record DNS (A, AAAA, CNAME, MX, NS, PTR, SOA, TXT, SRV)** | A: nama → IPv4. AAAA: → IPv6. CNAME: alias ke nama lain. MX: mail server domain (dengan prioritas). NS: name server zona. PTR: reverse. SOA: info otoritas zona (serial, refresh, TTL). TXT: teks (SPF, verifikasi). SRV: lokasi layanan (SIP, LDAP). | Isi utama file zona; salah satu record menyebabkan layanan tidak ditemukan. |
| 17 | **Serial Number SOA dan TTL** | Serial (format YYYYMMDDnn) harus dinaikkan setiap mengubah zona agar server sekunder menyalin. TTL: lama record boleh di-cache klien/resolver. | Perubahan DNS "tidak jalan" sering karena lupa menaikkan serial atau TTL lama. |
| 18 | **Authoritative vs Recursive/Caching DNS, Forwarder** | Authoritative: pemilik resmi data zona. Recursive: mencari jawaban untuk klien dari root → TLD → authoritative lalu menyimpannya. Forwarder: meneruskan kueri ke DNS lain (8.8.8.8). Server rekursif terbuka ke internet berbahaya (amplifikasi). | Menentukan peran DNS server sekolah: authoritative untuk domain lokal + recursive untuk klien internal. |
| 19 | **Primary (Master) dan Secondary (Slave) DNS, Zone Transfer (AXFR)** | Server sekunder menyalin zona dari primer lewat zone transfer sehingga layanan tetap ada saat primer mati. Batasi `allow-transfer` hanya ke sekunder. | Redundansi DNS; nama domain publik wajib punya minimal 2 NS. |
| 20 | **Pengujian DNS (nslookup, dig, host, named-checkconf)** | `named-checkconf` dan `named-checkzone` memeriksa sintaks; `dig @192.168.1.2 www.sekolah.sch.id` menguji jawaban; `dig -x 192.168.1.10` menguji PTR; klien diarahkan ke DNS server via DHCP. | Validasi konfigurasi DNS sebelum dipakai. |
| 21 | **Hosts File** | File pemetaan nama–IP lokal yang dibaca sebelum DNS: `/etc/hosts` (Linux), `C:\Windows\System32\drivers\etc\hosts` (Windows). | Uji cepat nama tanpa DNS atau blokir domain sederhana. |
| 22 | **Web Server (Apache HTTP Server, Nginx, IIS, LiteSpeed)** | Perangkat lunak penyaji situs web lewat HTTP/HTTPS. Apache (`apache2`, modul, .htaccess, direktori `/var/www/html`, konfigurasi `/etc/apache2/sites-available/`). Nginx (ringan, cepat, reverse proxy, `/etc/nginx/sites-available/`). IIS untuk Windows Server. | Menyajikan web sekolah, e-learning (Moodle), aplikasi PHP, dan halaman hotspot. |
| 23 | **Document Root, Index, dan Virtual Host** | Document root: folder file situs. Index: file default (index.html/index.php). Virtual host: satu server melayani banyak domain (name-based) dengan `ServerName`/`server_name` dan document root berbeda; aktifkan `a2ensite` lalu `systemctl reload apache2`. | Banyak situs di satu server dengan satu IP. |
| 24 | **HTTPS di Web Server (Certbot/Let's Encrypt, Self-Signed)** | Memasang sertifikat TLS: `certbot --apache -d domain` (gratis, otomatis diperbarui) untuk domain publik; `openssl` self-signed untuk lab; aktifkan `mod_ssl`, redirect HTTP→HTTPS. | Situs aman dan tidak ditandai "Not secure" oleh browser. |
| 25 | **LAMP / LEMP Stack** | Paket standar server web dinamis: Linux + Apache (atau Nginx = "E") + MySQL/MariaDB + PHP (Perl/Python). Instal `apt install apache2 mariadb-server php libapache2-mod-php php-mysql`. | Menjalankan WordPress, Moodle, aplikasi PHP sekolah. |
| 26 | **PHP dan PHP-FPM** | Bahasa skrip sisi server untuk web dinamis; PHP-FPM adalah pengelola proses PHP untuk Nginx/Apache event. File `php.ini` mengatur upload_max_filesize, memory_limit, dsb. | Aplikasi web populer (WordPress, Moodle, SIAKAD) berbasis PHP. |
| 27 | **CMS dan LMS (WordPress, Joomla, Moodle)** | Content Management System untuk situs (WordPress, Joomla, Drupal); Learning Management System untuk e-learning (Moodle, Chamilo). Dipasang di atas LAMP dengan database sendiri. | Situs dan e-learning sekolah tanpa memprogram dari nol. |
| 28 | **Pengujian Web Server** | Buka `http://ip-server` dan `http://namadomain` dari klien, `curl -I http://ip` (header), cek log `/var/log/apache2/access.log` dan `error.log`, `apache2ctl configtest`. | Memastikan situs tersaji dan menemukan penyebab error 403/404/500. |
| 29 | **Kode Status HTTP (200, 301, 403, 404, 500, 502)** | 200 OK; 301/302 redirect; 401/403 tidak berizin/dilarang (izin file, aturan); 404 tidak ditemukan; 500 error server (PHP/konfigurasi); 502/503/504 gateway/layanan bermasalah (backend mati, timeout). | Membaca masalah web server dengan cepat. |
| 30 | **Reverse Proxy dan Load Balancer (Nginx, HAProxy)** | Reverse proxy menerima permintaan dari internet lalu meneruskannya ke server internal (menyembunyikan backend, terminasi TLS, cache). Load balancer membagi permintaan ke beberapa server (round robin, least connection) dengan health check. | Banyak aplikasi internal lewat satu IP publik dan ketersediaan tinggi. |
| 31 | **Database Server (MySQL/MariaDB, PostgreSQL, SQL Server, MongoDB)** | Server penyimpan data terstruktur yang diakses aplikasi lewat SQL. MariaDB (port 3306) paling umum di praktik: `mysql_secure_installation`, buat database/user (`CREATE DATABASE; CREATE USER; GRANT`), bind-address, backup `mysqldump`. PostgreSQL (5432) untuk aplikasi besar. | Menyimpan data aplikasi web, e-learning, absensi, hotspot billing. |
| 32 | **phpMyAdmin dan Adminer** | Antarmuka web untuk mengelola MySQL/MariaDB (tabel, kueri, impor/ekspor). Harus diamankan (HTTPS, batasi IP, kata sandi kuat). | Administrasi database tanpa CLI. |
| 33 | **Backup Database (Dump) dan Restore** | `mysqldump -u root -p namadb > backup.sql` (ekspor) dan `mysql -u root -p namadb < backup.sql` (impor); dijadwalkan lewat cron dan disalin ke lokasi lain. | Data aplikasi bisa dipulihkan saat rusak/diretas. |
| 34 | **FTP Server (vsftpd, ProFTPD, Pure-FTPd, FileZilla Server)** | Server transfer file klasik. vsftpd: `apt install vsftpd`, konfigurasi `/etc/vsftpd.conf` (anonymous_enable, local_enable, write_enable, chroot_local_user, pasv_min/max_port), pengguna sistem sebagai akun FTP. Port 21 (kontrol) + 20/pasif (data). | Berbagi file ke banyak pengguna; kini disarankan FTPS/SFTP karena FTP tidak terenkripsi. |
| 35 | **Mode FTP Active vs Passive** | Active: server membuka koneksi data ke klien (sering diblok firewall klien/NAT). Passive: klien membuka koneksi data ke port pasif server (perlu range port pasif dibuka di firewall server). | Penyebab umum "bisa login tetapi tidak bisa list/upload". |
| 36 | **Pengujian FTP Server** | Dari klien: FileZilla/WinSCP atau `ftp ip-server`, login, upload/download, cek izin folder; log `/var/log/vsftpd.log`. | Memastikan akun, izin, dan mode pasif benar. |
| 37 | **File Server dan Samba (SMB/CIFS)** | Server berbagi folder/printer untuk klien Windows/Linux/macOS. Samba: `apt install samba`, `/etc/samba/smb.conf` (section share: path, browseable, writable, valid users), `smbpasswd -a user`, akses dari Windows `\\ip-server\share`. Port 445. | Penyimpanan bersama tugas siswa/guru dengan hak akses per pengguna. |
| 38 | **NFS (Network File System)** | Berbagi folder antar-Linux/Unix: `/etc/exports` (`/data 192.168.1.0/24(rw,sync)`), `exportfs -a`, klien `mount ip:/data /mnt`. | File sharing antar-server dan penyimpanan VM/container. |
| 39 | **NAS dan SAN** | NAS (Network Attached Storage): perangkat penyimpanan berjaringan berbasis file (SMB/NFS), misalnya Synology, QNAP, TrueNAS. SAN (Storage Area Network): penyimpanan berbasis blok (iSCSI, Fibre Channel) untuk server/virtualisasi. | Penyimpanan terpusat, backup, dan storage VM. |
| 40 | **Hak Akses File Server (Permission, ACL, Quota)** | Izin Linux (rwx, chmod/chown), ACL untuk izin lebih detail (`setfacl`), quota membatasi kapasitas per pengguna/grup; di Samba dipadukan dengan valid users/write list. | Pengguna hanya mengakses folder miliknya dan tidak menghabiskan disk. |
| 41 | **Print Server (CUPS, Windows Print Server)** | Server yang membagikan printer ke jaringan: CUPS (port 631, web admin) di Linux; Print Management di Windows Server. | Satu printer dipakai satu lab/kantor dengan antrian terpusat. |
| 42 | **Mail Server (Postfix, Dovecot, Exim, Sendmail, Zimbra, Exchange)** | Sistem email lengkap: MTA (Postfix, mengirim/menerima SMTP port 25/587/465), MDA/IMAP-POP3 (Dovecot, port 143/993/110/995), record MX dan A/PTR di DNS, webmail (Roundcube), anti-spam (SpamAssassin, Rspamd), TLS. Zimbra/Exchange/iRedMail adalah paket lengkap. | Email berdomain sendiri (nama@sekolah.sch.id) dan praktik yang menuntut pemahaman DNS + keamanan. |
| 43 | **MTA, MDA, MUA** | MTA (Mail Transfer Agent): mengirim antar-server (Postfix). MDA (Mail Delivery Agent): menaruh ke kotak surat dan melayani IMAP/POP3 (Dovecot). MUA (Mail User Agent): aplikasi pengguna (Thunderbird, Outlook, Gmail app, Roundcube). | Memahami alur email dari pengirim sampai penerima. |
| 44 | **Webmail (Roundcube, SquirrelMail, RainLoop)** | Aplikasi web untuk membaca/mengirim email lewat browser yang terhubung ke IMAP/SMTP server. | Pengguna mengakses email tanpa memasang aplikasi. |
| 45 | **Open Relay, Spam, dan Blacklist** | Open relay: mail server yang meneruskan email siapa pun (disalahgunakan spammer) → IP masuk blacklist (Spamhaus) → email ditolak. Cegah dengan autentikasi SMTP dan `mynetworks` ketat. | Menjaga reputasi mail server dan email sekolah sampai ke tujuan. |
| 46 | **Pengujian Mail Server** | Kirim antar-akun lewat webmail/Thunderbird, `telnet ip 25` (perintah EHLO, MAIL FROM, RCPT TO), periksa `/var/log/mail.log`, `dig MX domain`, uji `mail-tester.com` untuk skor spam. | Verifikasi menyeluruh layanan email. |
| 47 | **Proxy Server (Squid)** | Perantara HTTP/HTTPS dengan cache dan filter: `apt install squid`, `/etc/squid/squid.conf` (http_port 3128, acl, http_access allow/deny, cache_dir, blokir situs/kata kunci, jam akses), transparent dengan NAT redirect port 80. Log `/var/log/squid/access.log`. | Kontrol dan pencatatan akses web; termasuk elemen konfigurasi perangkat di CP. |
| 48 | **NTP Server (chrony, ntpd)** | Server waktu lokal yang menyinkron ke internet dan melayani semua perangkat LAN: `apt install chrony`, `allow 192.168.0.0/16`, cek `chronyc sources`/`ntpq -p`. | Jam seragam untuk log, autentikasi, dan ujian online. |
| 49 | **Syslog Server (rsyslog, syslog-ng, Graylog)** | Server penampung log dari router, switch, AP, dan server lain (UDP/TCP 514), disimpan per host dan dianalisis. | Log terpusat memudahkan investigasi dan tidak hilang saat perangkat direset. |
| 50 | **Server Autentikasi (FreeRADIUS, LDAP/OpenLDAP, Active Directory)** | FreeRADIUS: `apt install freeradius`, `clients.conf` (NAS + secret), `users`/SQL untuk akun, uji `radtest`. OpenLDAP/AD: direktori pengguna terpusat untuk login banyak layanan. | Satu akun untuk Wi-Fi, hotspot, VPN, dan login komputer. |
| 51 | **Active Directory Domain Services (AD DS), Domain Controller, Group Policy** | Layanan direktori Windows Server: Domain Controller menyimpan akun dan mengautentikasi login (Kerberos); komputer di-join ke domain; Group Policy (GPO) menerapkan pengaturan/kebijakan massal (wallpaper, pembatasan, pemetaan drive). | Mengelola ratusan PC dan pengguna sekolah/kantor Windows secara terpusat. |
| 52 | **VPN Server (OpenVPN, WireGuard, SoftEther, L2TP/IPsec, pfSense)** | Server yang menerima koneksi VPN pengguna jauh: buat sertifikat/kunci (OpenVPN easy-rsa, `wg genkey`), tentukan subnet VPN (10.8.0.0/24), push route ke LAN, aktifkan IP forwarding dan NAT, buka port (UDP 1194/51820) di firewall, bagikan file konfigurasi klien. | Akses aman ke server/CCTV sekolah dari rumah; termasuk layanan wajib di CP. |
| 53 | **IP Forwarding dan Server sebagai Router/Gateway** | Mengaktifkan penerusan paket di Linux (`sysctl net.ipv4.ip_forward=1`) lalu NAT dengan iptables (`-t nat -A POSTROUTING -o eth0 -j MASQUERADE`) sehingga server berfungsi sebagai router. | Membangun gateway/firewall/VPN berbasis Linux. |
| 54 | **Streaming dan Video Conference Server (Jitsi Meet, BigBlueButton, Nginx-RTMP)** | Server konferensi video mandiri (Jitsi, BBB untuk kelas daring) dan streaming (Nginx-RTMP, OBS). Butuh CPU/bandwidth besar dan port UDP 10000 (Jitsi). | Kelas daring dan siaran acara sekolah dengan server sendiri. |
| 55 | **VoIP Server (Asterisk/Issabel/FreePBX) sebagai Layanan Jaringan** | Server telepon IP yang dipasang seperti layanan lain: instal, buat ekstensi SIP, uji softphone, buka port 5060 dan RTP. | Menghubungkan materi VoIP dengan administrasi server. |
| 56 | **Control Panel Hosting (cPanel/WHM, Plesk, DirectAdmin, CyberPanel, aaPanel, Webmin/Virtualmin)** | Antarmuka web untuk mengelola hosting: membuat akun domain, email, database, FTP, SSL, file manager, statistik, backup, tanpa mengetik perintah. cPanel/Plesk berbayar; CyberPanel/aaPanel/Virtualmin gratis. | Mengelola banyak situs/pelanggan hosting secara cepat; praktik CP "control panel hosting". |
| 57 | **Web Hosting** | Layanan menyewakan ruang server yang selalu online untuk menempatkan situs web beserta domain, email, dan database. | Situs sekolah/usaha online tanpa mengelola server sendiri. |
| 58 | **Shared Hosting** | Banyak situs pelanggan berbagi satu server dan sumber dayanya (CPU, RAM, IP) dengan isolasi akun; murah tetapi kinerja saling memengaruhi dan akses terbatas (tanpa root). | Pilihan ekonomis untuk situs kecil; siswa belajar membuatnya dengan control panel di server Linux. |
| 59 | **VPS (Virtual Private Server)** | Server virtual dengan sumber daya terjamin dan akses root penuh, dibuat dari virtualisasi (KVM, OpenVZ/LXC) di server fisik penyedia (IDCloudHost, Niagahoster, DigitalOcean, AWS Lightsail). | Menjalankan layanan sendiri (web, VPN, bot) dengan biaya puluhan–ratusan ribu per bulan; sarana latihan nyata administrasi server. |
| 60 | **Dedicated Hosting / Dedicated Server** | Satu server fisik utuh disewa untuk satu pelanggan: kinerja maksimal, kendali penuh, biaya tertinggi. | Aplikasi besar/ramai atau kebutuhan keamanan/kepatuhan khusus. |
| 61 | **Cloud Hosting dan Managed Hosting** | Cloud hosting: sumber daya dari kumpulan server (bisa naik-turun sesuai beban, bayar per pakai). Managed: penyedia mengurus OS, keamanan, dan backup untuk pelanggan. | Memahami pilihan hosting modern dan tanggung jawab masing-masing pihak. |
| 62 | **Domain, Registrar, dan Name Server Delegation** | Domain didaftarkan melalui registrar (PANDI untuk .id, Niagahoster, Rumahweb, Namecheap); pengaturan NS di registrar menunjuk ke DNS server hosting; domain .sch.id butuh surat sekolah. | Menghubungkan nama domain dengan server hosting/DNS sendiri. |
| 63 | **Uptime Hosting dan SLA Hosting** | Janji ketersediaan penyedia (99,9%) dan kompensasinya; dipantau dengan layanan uptime monitor. | Memilih penyedia dan menagih hak saat layanan turun. |
| 64 | **Virtualisasi Server (Proxmox VE, VMware ESXi/vSphere, Hyper-V, KVM, XCP-ng)** | Hypervisor tipe 1 untuk menjalankan banyak server virtual di satu mesin fisik: Proxmox VE (open source, KVM + LXC, web UI) sangat populer di sekolah; ESXi standar enterprise; Hyper-V bawaan Windows Server. | Lab server lengkap (DHCP, DNS, web, mail, VPN) dalam satu PC/server; efisiensi dan snapshot. |
| 65 | **VM Template, Clone, Snapshot, Live Migration, HA Cluster** | Template: VM induk untuk digandakan. Clone: salinan VM. Snapshot: titik pemulihan. Live migration: memindahkan VM antar-host tanpa mati. HA cluster: VM otomatis pindah jika host rusak. | Pengelolaan VM yang cepat dan tahan gangguan. |
| 66 | **Container dan Docker (Image, Container, Dockerfile, Volume, docker compose)** | Image: paket aplikasi siap jalan (dari Docker Hub). Container: instance image yang berjalan. Dockerfile: resep membangun image. Volume: penyimpanan persisten. docker compose: mendefinisikan beberapa container (web + db) dalam satu file YAML. Perintah: `docker run -d -p 80:80 nginx`, `docker ps`, `docker logs`. | Memasang layanan (Nginx, MariaDB, Zabbix, Nextcloud) dalam menit dan konsisten. |
| 67 | **LXC/LXD dan Portainer** | LXC: container sistem (seperti VM ringan) yang dipakai Proxmox. Portainer: antarmuka web mengelola Docker. | Alternatif ringan VM dan pengelolaan container visual. |
| 68 | **Infrastructure as Code dan Ansible** | Menyatakan konfigurasi server dalam file (YAML) yang bisa dijalankan berulang: Ansible (tanpa agen, lewat SSH, playbook), Terraform (cloud). | Mengonfigurasi 30 PC lab atau 10 server secara identik dan otomatis. |
| 69 | **Sistem Kontrol dan Monitoring** | Pemantauan kesehatan server/jaringan (CPU, RAM, disk, trafik, layanan, suhu, uptime) dan pengendalian (restart layanan, notifikasi, otomatisasi) secara terpusat. | Mengetahui masalah sebelum pengguna mengeluh dan mendukung SLA. |
| 70 | **Zabbix** | Platform monitoring open source lengkap: agen di server, SNMP untuk perangkat, template, grafik, peta, trigger, dan notifikasi (email/Telegram). Mudah dipasang via Docker/paket. | Monitoring standar industri yang bisa dipraktikkan di sekolah. |
| 71 | **Cacti, Nagios, PRTG, LibreNMS, Observium** | Cacti: grafik trafik SNMP berbasis RRDtool (klasik di SMK). Nagios/Icinga: pemantauan status layanan dan alert.
